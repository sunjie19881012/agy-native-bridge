# 原生会话桥接与中心化协作平台的分工

`agy-native-bridge` 适合从 Antigravity 调度用户能在原窗口查看的 Codex 或 DSH 会话。中心化协作平台适合需要跨人、跨项目长期管理任务和权限的团队。

| 需要解决的问题 | 原生会话桥接 | 中心化协作平台 |
|---|---|---|
| 数据与连接 | 原生会话是状态源。本机缓存配对、星标与心跳，按需打开桥接连接 | 由平台集中管理项目、任务状态、成员、审计与服务连接 |
| 常用场景 | 从当前对话给指定原生会话派发、回读、审查、验收，或在单台 Linux 主机上进行有限轮次的实现与评审接力 | 跨团队任务队列、多角色审批、长期追踪、交接和组织级权限 |
| 权限与运行 | 沿用目标原会话已生效的模型与审批设置，审批在原窗口处理 | 适用平台自身的身份、授权、审批和运维规则 |
| 能力边界 | 无全局调度队列、跨项目审计中心或集中凭据库，Sidecar 配对是本机视图 | 需要依据具体平台确认会话同步、离线体验和端侧委托能力 |

同一工作流可以在协作平台记录任务与验收结论，在原生会话桥接里执行编码和自测。建立一条明确的派发责任链，指定一方调用原会话。涉及同一 Codex 工作区和轮次时，保持既定的桌面或显式 daemon 路径，避免从两个入口并发写入同一个会话。

有配对或用户指定协作窗口时，Antigravity 负责澄清、设计、派发、审查与验收，Codex 或 DSH 负责改代码和自测。用户明确要求 Antigravity 直接动手时，由本端执行。
